## What is being adopted, and why

Decided with the user 2026-07-27/28: **push + clip**, both layers.

- **The push** (Stage 2's missing upward half). The existing clip only caps
  from above; it cannot fix a max-worthy player the model prices below his
  ceiling, and the max zone is underpredicted by $4.27M. Where
  `P(max) ≥ τ = 0.52`, push the latent toward the ceiling:
  `pushed = latent + P(max) × (1.05 × max_eligible_pct − latent)`, then the
  ordinary Stage-2 clip. **τ = 0.52 and the 1.05 margin are pre-registered
  constants — do not re-tune either.** τ came from the sweep's
  `expected win − expected collateral` rule; the margin has been frozen since
  phase 1.
- **The extension clip** (Stage 3). For rows that ARE first-paying-year
  extensions, additionally clip at their own `ext_cap_pct`. This is what
  catches the push's collateral: Aldridge, Smart and Brunson are pushed at a
  tier ceiling they cannot legally reach, and the clip returns them to the
  law.

Measured on the harness (`scripts/eval_told_clip.py`), against the champion:

| | A1 | A2 | B1 fwd | 2026 origin | max-zone MAE |
|---|---|---|---|---|---|
| champion | 0.7865 | 0.8341 | 0.8342 | 0.7964 | $4.297M |
| push only | 0.7849 | 0.8381 | 0.8174 | 0.7980 | $3.179M |
| **push + clip** | **0.7988** | **0.8517** | **0.8355** | **0.7989** | **$3.179M** |

The clip alone (no push) was also measured — A1 0.7945, ΔSel +0.0088 at
t = 1.48 — and the user chose push + clip, because the max zone's $1.12M is
the problem the whole line exists to solve.

**It does not clear t > 2** (ΔSel +0.00856, t = +1.11) and is adopted anyway,
on the same grounds as v7.4x, v7.9x and v7.13x: it enforces a legal bound
rather than fitting a parameter. Predicting $39.68M for Marcus Smart was not
inaccurate, it was impossible. Everything else improves — A1, A2, MAE, the
max zone, and the forward number at every origin.

## The one property that must hold

**When the route is unknown, the model must behave exactly as it does today.**
An unsigned free agent has no extension flag, so the clip is a no-op for him
and the prediction must be bit-identical to the current pipeline's — except
for the push, which applies to everyone. Verify this explicitly: run the
current `export_web.py` output and the new one on the 2026/2027 FA set and

## Part 1 — the composition, in one place

Put Stage 3 in ONE function with an explicit signature, so no consumer
re-implements it:

```
stage3(pred, *, is_extension, ext_cap_pct) -> pred
```

with the contract stated in the docstring: it only ever lowers a prediction;
it is a no-op where `is_extension` is false or `ext_cap_pct` is NaN; and it
never reads the target. `attach_extension_cap` already produces both inputs.

The push belongs with Stage 2 (it is the upward half of the same bound), so
compose as: `latent → push → clip(lo, hi) → stage3`.
